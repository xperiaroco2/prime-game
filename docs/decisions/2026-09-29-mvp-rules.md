## Context
M2 starts the real game, and the rules it builds need a source every session can read: the chat in which the engineer
decided them is not visible to other sessions. Lockdown Protocol is the main reference; the look is low-poly and first
person, roughly like How to Fish. The goal is an extensible framework on that base, not a copy: roles, task types, win
conditions and game modes are modular, so a new mechanic needs no rewrite of the core. Visuals stay minimal
(primitives, simple low-poly models); the focus is on mechanics. Everything key is configurable.

The phases these rules run in: [game modes define the phases](2026-09-29-game-modes-define-the-phases.md). Hosting,
disconnects and the network: [listen server and message layer](2026-09-29-listen-server-and-message-layer.md).

## Decision

### Roles
- Two roles: **Crew** and **Dissident**. Neither has tasks of its own: the tasks are shared (below), any living
  player may do any subtask, and a subtask a dissident completes counts toward the shared progress like anyone's.
- The number of dissidents is a lobby setting from 0 to N−1 (N = players). Dissidents know each other.
- Players read the crew as **Engineers**: the role's display name is "Engineer", the side's "Engineers", both
  provisional until the game's setting is known; the ids in the data stay `crew`
  ([vision revision 1](2026-10-01-vision-revision-1.md), V12). These rules say "crew" for the side.
- **Dissidents sabotage actively** ([vision revision 1](2026-10-01-vision-revision-1.md)): in the MVP by hiding
  packages, carrying one away and putting it down where the engineers will not find it soon, anywhere a put-down
  allows. Anyone may already carry any package, so no new mechanic is needed. A level keeps every spot a put-down
  reaches reachable for a pickup (`levels/CLAUDE.md`).
- **Living** means upright: a knocked-down (downed) player is not living, wherever these rules say "living" (V4).

### Win conditions
- The **crew** wins when all tasks are done before the match timer ends. This is the crew's only way to win.
- The **dissidents** win when the timer ends with tasks left, or when every crew member has left the match (no crew
  present: a downed or dead crew member is still present). Killing takes time from the crew and never wins
  ([vision revision 1](2026-10-01-vision-revision-1.md), V10; it replaces "or when every crew member is dead").
- Killing a dissident gives the crew nothing by itself.
- With 0 dissidents, the timer ending is still a dissident win: the crew loses.

### Tasks
The engineer's decision of 2026-09-30 (#79), which replaces the per-player tasks of 2026-09-29:
- **Tasks are shared.** No task is dealt to a player and nobody owns one: any living player does any subtask. Crew
  and dissidents alike have no tasks of their own. The HUD shows the shared progress, and the Tab task screen each
  task's (HUD below).
- **How many tasks:** a match setting `tasks`, from 1 to the number of task types in the pool. Each task of a match
  is a different task type: a type appears at most once. Today the mode has one type, Delivery, so it is 1.
- **Which tasks:** drawn at random from the pool, the mode's task types. The host can ban task types in the lobby,
  which takes them out of the pool; the upper bound of `tasks` is then the number of types not banned. A ban that
  would leave fewer types than `tasks`, or none at all, is refused (a placeholder rule, "not a decision"; the host
  lowers `tasks` in the same change).
- **Subtasks:** each task type has its own subtasks setting. Delivery's is the number of packages: 1 to 10,
  default 6 (a placeholder, "not a decision").
- **Zero:** a task with no subtasks is done; with no tasks at all, "every task done" holds.
- The settings *tasks per player* and *subtasks per task* are gone.
- The only MVP task type is **Delivery**:
  - At match start, N packages (N the `packages` setting, whatever the player count) are scattered at random over
    the map's package spawn points.
  - Each package has its own destination: in the MVP, a circle on the map, one per package. The circles are also
    placed at random at match start, over the map's circle spawn points. Each package has a unique colour from a
    palette of 10, and its circle has the same colour, so a player sees which circle a package belongs to.
  - A circle is an invisible cylinder standing on the floor: radius 1 m (game design, in the data, not a lobby
    setting) and height 2 m (a placeholder, "not a decision").
  - One package is one subtask.
  - A subtask is done when the package **rests inside its destination circle, however it got there** (put down,
    swapped, dropped by a dying or leaving player; later thrown): its centre, its rest position, is inside its
    circle's cylinder. Standing on the circle while holding it is not enough. (The engineer's correction in #32,
    2026-09-29; it replaces "put down so that it rests on its circle". The cylinder is #79's.)
  - A delivered package counts for good and is no longer interactive: nobody can pick it up (Q3). Its circle is
    shown as done.
  - Any living player may carry and deliver any package, so an idle player cannot block the crew. A downed carrier
    keeps the package until a revive or death, and at death it drops at the body (below).
- New task types must be addable later, for example "stand in a zone for N seconds" (#36).

### Items
Two hands ([vision revision 1](2026-10-01-vision-revision-1.md), V5 and V13; it replaces "one hand slot" and
"holding a weapon means not holding a package"):
- Two one-handed slots: the **hand** and the **belt**. The belt holds at most one item and is visible on the body to
  everyone, as the hand item is. A key swaps hand and belt.
- Every item kind is one- or two-handed (`hands`: 1 or 2). The knife is one-handed. The Delivery package is
  two-handed: on the ground or in the hand, never on the belt.
- Any item can be picked up and put down. The picked item always goes to the hand. A one-handed item in hand moves to
  an empty belt; otherwise the hand item is swapped: it rests where the picked item lay, the package too.
- With two items, one is always in hand, never both on the belt.
- Only the hand item is used or put down. In the MVP a key places it on the ground in front of the player; physics
  throwing comes later (#37).
- The swap is refused while the package is in hand, so a package carrier cannot draw a belted knife. One player may
  carry both knives, one in hand and one visible on the belt.
- A downed player keeps both slots; at death both drop at the body; a player who leaves drops both where they stood.

### Health and stamina
- Every player has health and stamina. At 0 health the player is knocked down (below).
- Sprint (Shift) speeds movement up and spends stamina; a jump spends stamina; a weapon hit spends stamina.
- Stamina regenerates while it is not being spent. Health does not regenerate in the MVP (Q4).
- Each player sees only their own health and stamina (Q5).

### Collisions
Living players never pass through each other, but a body cannot block a passage (the engineer's decision of
2026-09-30 in #46, read back and confirmed):
- Walking into a player pushes them: you both move on, slower than your own speed. You slow down, and they are pushed
  at that reduced speed (the push speed factor, a placeholder of about half).
- Head-on, the pushes along the line of contact cancel, so nobody advances. The bodies are round, so any sideways
  motion or a small angle makes them slide off each other and part; even a perfectly straight contact gets a tiny
  sideways drift, so the two never freeze like two walls. It should feel lively, not mechanical.
- A downed player pushes nobody and is pushed by nobody, and the dead have no avatar (no ghosts since
  [vision revision 1](2026-10-01-vision-revision-1.md)).
- Being pushed costs no stamina: sprint spends stamina only on the player's own movement, so a pushed player holding
  Shift pays nothing for the push (the engineer's decision of 2026-09-30, #46).
- The network model does not change: each client moves only its own player. The pushed player's client moves its
  player from the pusher's interpolated motion (about 0.1 s late), and the host tolerates overlap and does not
  correct it (ARCHITECTURE §7.1 "Pushing apart").

### Weapon
- The base weapon, a **knife**, is an item taken into the hand. Knives are scattered at random at match start, like
  packages; their count is a lobby setting (Q1).
- Using a knife hits: every living player inside the hit zone in front takes damage, except an invulnerable one
  (below), and the hit spends stamina (Q2).
- The hit zone (angle and reach) is set per weapon. The knife's zone is narrow and short, so that it almost never
  touches two players, because players push each other apart. Later weapons may have a wider angle and a longer
  reach.
- Anyone can hit anyone.

### Knockdown, death and respawn
Replaced by [vision revision 1](2026-10-01-vision-revision-1.md) (#126; its ADR has the details and what is still
open). There are no ghosts; the old "Death and ghosts" section is in this file's history.
- **Knocked down** at 0 health, for the knockdown time: the player falls where they stand and the camera goes third
  person above the body (no higher than the eye height above it, colliding with the level). A downed player can only
  **crawl** (the crawl speed, the step height, no jump, sprint or stamina cost, no collision with any player) and **give
  up**. They keep their items and cannot use, put down, pick up or swap them. They cannot be hit. Crawling into a circle
  with the package and giving up, so that it drops there and counts, is legal (V4).
- **Revive** (V3): any living player, dissidents included, holds E for the raise time within reach and in sight of a
  downed player. The knockdown timer pauses while someone raises, and the downed player does not crawl meanwhile
  (the ADR's "Needs the engineer" 8). Releasing E, moving out of reach, being hit or
  downed, starting another action, or the downed player giving up cancels the raise. A revived player stands up with
  the revive health. A raise stopping is public and names no cause; one that stops in the tick of a swing confirms
  that the swing hit the raiser, an accepted exception to #32's "no hit confirmation" (the ADR's "Needs the
  engineer" 7).
- **Give up:** a downed player can press a button to die at once, even while someone is raising them.
- **Dead:** not raised within the knockdown time, or gave up. Both slots drop at the body, which stays until its
  player respawns (V7). The dead player **spectates** a living or downed player, dissidents included, through that
  player's camera, built on their own client from the public snapshot: no HUD, health, role or private event of the
  target (V1). The first target is a random living player, a key cycles through the living and downed, the camera
  switches by itself when its target goes down, dies or leaves, and the target is never told (V9). The dead hear no
  voice (the world sounds around their target and lift music instead) and are heard by nobody (V11). What they saw is
  fair game after the respawn (V1).
- **Respawn** (V6) after the respawn time, at a random free respawn point (markers tagged `respawn`), with the role
  kept, full health and stamina and empty hands. The body is removed.
- **Invulnerable** (V8) for the invulnerability time after a revive or a respawn: strikes skip the player, pushing
  works as usual, the player's own attack ends it, everyone sees it, and nobody has it at the start of a round.
- Knockdowns, revives, deaths and respawns are public and name no attacker. The knockdown and respawn countdowns are
  shown only to their own player (V13).

### Voice
- Proximity voice between the living. The lobby uses proximity voice too.
- Nobody hears a downed or dead player, under any voice rule (an engine invariant). A downed player hears the living
  by proximity from where they lie. The dead hear no voice ([vision revision 1](2026-10-01-vision-revision-1.md),
  V11; it replaces the dead's own proximity group of #32).

### Meetings and voting
None. The meetings mode (#35) is dropped by [vision revision 1](2026-10-01-vision-revision-1.md): deduction is not
central to this game.

### Match loop
1. Players join the host and arrive in the lobby scene, where they can walk and talk and nothing else.
2. Each player presses Ready.
3. When all are ready, a 5-second countdown starts; anyone un-readying, joining or leaving cancels it.
4. After the countdown everyone loads the game scene; roles are dealt and packages scattered.
5. At the end, an end screen says only which side won: "The Engineers won" or "The dissidents won" (the side's
   display name, vision revision 1). It names no players and shows no roles; players discuss their roles in the lobby
   afterwards. The host's button returns everyone to the lobby for the next match. While the end screen is up the
   game is frozen: the screen is black apart from the result, and nobody hears anybody. (The engineer's correction
   in #32, 2026-09-29; it replaces "shows the winner and every role".)

Voice exists only in the lobby (its countdown included) and in the round; there is none while loading or on the end
screen (#32).

### Player names
The engineer's decision of 2026-09-30 on #58 (the answer to item 1 of PR #72's questions, read back and confirmed):
- The host names every player `Player<n>`, with n counted by join order over the whole session: Player1, Player2,
  Player3, and so on. The name a client sends when it joins is ignored in the MVP.
- A number is never reused in a session: Player1 to Player3 join, Player2 leaves, and the next joiner becomes
  Player4, not Player2. The count carries on after End → Lobby.
- After the MVP (#73): a player sets their own name and body colour (10 preset colours, no colour picker), and a
  player who reconnects gets their old number back.

### Match settings
Changed by the host in a lobby UI between matches: match duration (minutes); tasks (1 to the task types not banned);
the banned task types; each task type's subtasks (Delivery: packages, 1 to 10); dissidents (0 to N−1); knives. What
the settings demand of the map (packages, circles) is shown next to them (#79).

### HUD
Health, stamina, the hand item and the belt item; a package also shows its destination. The shared task progress:
nobody has tasks of their own (#79). A **task screen** on Tab, for every player, living, downed or dead: the match's
tasks, each with a short description and its shared progress, and a map of the task circles (where tasks are done),
the items' spawn points and the viewer's own position (none for a dead viewer, who has no avatar; never the
spectate target). The map never shows an item's current position and never other players
([vision revision 1](2026-10-01-vision-revision-1.md), V2).

## The engineer's answers to #32 (2026-09-29)
The answers below are kept as history. Where they speak of ghosts, the dead's voice or one hand slot,
[vision revision 1](2026-10-01-vision-revision-1.md) replaces them.

Asked in #32's session as one batched question; the engineer answered "A" (the recommended option) to each, except
where noted.
- **Q7 At 0 stamina:** walking always works. Sprint, jump and a knife hit need at least their full cost, so they are
  unavailable until stamina regenerates that far. For sprint the full cost is one second of sprinting; once started,
  a sprint lasts until stamina reaches 0 or Shift is released.
- **Q8 Settings defaults:** placeholders marked "not a decision", in the table above.
- **Leaving or hanging during Loading** (roles are not dealt yet): that peer is dropped and the round starts with
  the peers that confirmed. A peer that has not confirmed within the loading timeout counts as leaving.
- **What each player learns in the base mode:** everything physical is public to every player of the match: where
  the living are, bodies and whose they are, items on the ground and in hands, a package's destination, the shared
  task progress, knife swings. Hidden: roles (except that dissidents know each other), a player's own tasks (none
  since #79: tasks are shared, and everything about them is public), their health and stamina, damage (only the
  victim learns it; the attacker gets no hit confirmation, except through the public knockdown and a raise that
  stops in the tick of the swing: vision revision 1), and ghosts (only the dead saw them; vision revision 1
  removed ghosts: a dead player spectates from the public snapshot on their own client, and whom they watch never
  leaves it). The interface does not announce deaths. Positions are not hidden behind walls: that would protect
  against cheating clients, which nobody asked for.
- **A client leaving mid-round:** the avatar disappears, everyone sees "X left", and no body stays. Both slots drop
  where the player stood (vision revision 1; it was "the held item"); the packages stay in the game.
- **Voice on the end screen** (the engineer's own answer): none; the game is frozen and nobody hears anybody (loop
  step 5).
- **Small rules:**
  - Picking an item up with a full hand swaps them (the engineer's own answer): the held item is put down where the
    picked-up item lay. Vision revision 1 (V5) keeps the spot and adds the belt: a one-handed item in hand moves to
    an empty belt instead; otherwise it is swapped as here, the package too (Items above).
  - A weapon has a minimum time between hits (the knife's is in the table).
  - The host changes the settings only in the lobby phase; a change un-readies nobody; during the countdown the
    settings are locked.
  - Several things in one tick: the tick's commands apply in the order the host received them, and the first win
    condition met ends the round. The timer is checked after the tick's commands, so a delivery in the last tick
    counts.
  - A dying player's items drop at the body ([vision revision 1](2026-10-01-vision-revision-1.md): both slots, and
    no ghost).
  - New placeholder numbers: in the table above.

## The engineer's answers Q1 to Q6 (2026-09-29)
Q6 and its corrections below are history: vision revision 1 removed ghosts.

- **Q1 Where knives come from:** scattered at random at match start like packages; the count is a lobby setting.
- **Q2 What a hit damages:** every living player in the hit zone. The zone is set per weapon (angle and reach), and
  the knife's is so narrow and short that it almost never touches two players, because players' colliders push each
  other apart. Later weapons may have a wider angle and a longer reach.
- **Q3 A delivered package:** it counts for good and can no longer be picked up.
- **Q4 Regeneration:** stamina regenerates while not being spent; health does not regenerate in the MVP.
- **Q5 Other players' health:** each player sees only their own.
- **Q6 How ghosts move:** neither option as asked. Ghosts fly, faster than the living, but do not pass through walls;
  for now their collider is the same as a living player's. Other ghosts see them as a small sphere, like a head. They
  do not collide with the living. (Corrected on 2026-09-30, see below: "fly" was the look, not the movement.)

Corrected by the engineer the same day: ghosts only watch, talk and move (faster than the living), and with 0
dissidents the timer ending is a dissident win.

Corrected by the engineer on 2026-09-30 in #46: in Q6 "fly" was the look (a floating head with no legs), not the
movement. Ghosts move like the living (no flight, no fly-down key), at 1.3 times the living's walk and sprint speeds,
with the living's jump height and unlimited stamina (the section "Death and ghosts", replaced by vision revision 1).
