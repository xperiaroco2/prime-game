# One file per entry for interventions and asset credits

- **Status:** Accepted
- **Date:** 2026-09-28
- **Deciders:** the engineer (Phase A decision session)

## Context
Two branches that each append a block to the end of the same file conflict (tested locally). `merge=union` avoids
that locally but can drop identical lines, and GitHub's merge button likely ignores `.gitattributes` (inferred, not
tested on our repo).

## Decision
- Interventions: `docs/interventions/YYYY-MM-DD-<who>-<slug>.md`. `docs/INTERVENTIONS.md` becomes a pointer.
- Credits: `docs/credits/<asset-slug>.md`. `CREDITS.md` is generated by `tools\run.cmd credits`, and `check` verifies
  that every LFS asset has a credits file.

## Alternatives
- Single files with `merge=union` and a rebase before every merge.
- Single files written only by the engineer's agent.

## Consequences
Deviates from KICKOFF §5.2 (one append-only file). No merge conflicts on these logs. The existing entry moved on
2026-09-28.
